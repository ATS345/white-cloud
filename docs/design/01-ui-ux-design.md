## 4. 响应式设计

### 4.1 断点设计

| 断点 | 屏幕宽度 | 设备类型 | 布局 |
|------|----------|----------|------|
| **xs** | < 640px | 手机 | 单列布局 |
| **sm** | 640px - 768px | 平板 | 双列布局 |
| **md** | 768px - 1024px | 小屏笔记本 | 三列布局 |
| **lg** | 1024px - 1280px | 笔记本 | 四列布局 |
| **xl** | > 1280px | 桌面 | 多列布局 |

### 4.2 响应式策略

#### 4.2.1 布局调整

- **移动端**：单列布局，垂直排列
- **平板**：双列布局，适当调整间距
- **桌面**：多列布局，充分利用空间

#### 4.2.2 组件适配

- **导航**：移动端折叠为汉堡菜单
- **卡片**：根据屏幕宽度调整大小和数量
- **表单**：移动端全屏宽度，桌面固定宽度
- **字体**：根据屏幕尺寸调整字体大小

#### 4.2.3 性能优化

- **图片**：响应式图片，根据屏幕尺寸加载合适大小
- **资源**：移动端加载简化版本
- **交互**：移动端优化触摸交互

## 6. 设计规范

### 6.1 命名规范

#### 6.1.1 组件命名

- **PascalCase**：组件名称（如：GameCard）
- **camelCase**：变量和函数（如：gameList）
- **kebab-case**：CSS类名（如：game-card）

#### 6.1.2 文件命名

- **组件文件**：组件名称.tsx（如：GameCard.tsx）
- **样式文件**：组件名称.module.css（如：GameCard.module.css）
- **类型文件**：types.ts（如：game.types.ts）

### 6.2 设计原则

1. **一致性**：统一的设计语言，保持视觉一致性
2. **简洁性**：简洁明了的界面，减少视觉干扰
3. **可用性**：易于使用，符合用户习惯
4. **可访问性**：支持无障碍访问
5. **响应式**：适配不同设备和屏幕尺寸
6. **性能**：优化加载速度和交互响应

### 6.3 设计流程

1. **需求分析**：理解业务需求和用户需求
2. **用户研究**：用户调研，用户旅程
3. **概念设计**：线框图，低保真原型
4. **视觉设计**：高保真原型，设计系统
5. **交互设计**：微交互，动效设计
6. **用户测试**：用户测试，反馈收集
